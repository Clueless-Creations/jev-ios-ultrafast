# Add Jev to a coding agent's app workflow

Use the same CLI and skill with any shell-capable coding agent. No agent-specific scenario language or XcodeBuildMCP installation is required.

Install Jev in a Python 3.11+ environment using the [README](../README.md#quick-start). Put standalone AXe on the Mac's PATH or set `JEV_IOS_AXE`. Keep gateway credentials in the coordinator environment, not in the app repository.

## Initialize the app repository

```sh
jev-ios init --bundle-id com.example.app
```

The scaffold contains a scenario, suite, local skill, guide and executable wrapper. Init leaves your existing `AGENTS.md` and `CLAUDE.md` unchanged. Add this instruction to the appropriate existing guide after reviewing it:

> For user-facing iOS changes, read `.jev-ios/AGENT.md` and `.jev-ios/SKILL.md`. Define the intended observable outcome, run the relevant Jev suite after building/installing the app, and inspect failures without weakening acceptance criteria.

`--force` only replaces unchanged files recorded as generated by this version of init. It does not discard edited tests. An older scaffold without ownership metadata must be reconciled or moved aside deliberately.

## Define the first flow

Inspect the authorized installed app:

```sh
jev-ios inspect --udid "$SIMULATOR_UDID" --bundle-id com.example.app --launch
```

Replace `.jev-ios/smoke.json` using exact observed labels. This example is a template for an app exposing these controls, not a universal settings test:

```json
{
  "schema": "jev-ios/scenario/v1",
  "name": "Notification settings",
  "goal": "Open notification settings and reach the push-notification controls.",
  "expect_labels": ["Notifications", "Push notifications"],
  "allow_labels": ["Settings", "Notifications"],
  "allow_scroll": false,
  "text_values": {},
  "max_steps": 6,
  "min_probability": 0.55
}
```

Also replace the suite's `start_labels` with exact labels visible after the fixture app relaunches. Configure app-supported test launch arguments when needed. Relaunch is not a database reset.

For an unfamiliar area, first use `jev-ios learn` with an explicit list of approved navigation labels, then inspect the destination again before choosing assertions. Maps orient the agent; product intent defines success.

## Run and scale

```sh
.jev-ios/run-smoke.sh
```

The wrapper uses `SIMULATOR_UDID` when set, otherwise already booted local iOS simulators. It creates a new result directory on every run. Add `/runs/` to the app repository's `.gitignore` and do not upload private traces by default.

Once devices have independent fixture accounts/data, configure a device pool and use the [parallel suite commands](parallel-testing.md). Choose `shard` for fast per-change checks and `matrix` for explicit device coverage. Keep shared-fixture serialization until isolation is real.

The coding agent should consume the final summary first, then only the relevant failed traces. A matrix exit code of 0 requires evidence for every selected cell. Provider errors, missing starts, skipped work, and uncertain input are distinct from product regressions.

For deliberate reproduction, `jev-ios reproduce` prepares a frozen-scenario plan by default. Review it, repair/reset fixture state, and add `--execute` to run it. Never replay a recorded tap whose outcome is unknown.

## Keep the claim narrow

A successful Jev scenario proves its exact visible labels, not a backend write, pixel quality, or all possible journeys. Keep unit, integration, visual, and release checks. Supply `--app-revision` when you know the installed build identifier; a local Git SHA alone does not identify the binary on the device.
